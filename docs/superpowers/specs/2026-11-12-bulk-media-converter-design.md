# Bulk Media Converter

Build a local Python desktop application matching the supplied charcoal and teal bento dashboard. Use pywebview for native integration, Pillow for images, and subprocess-driven FFmpeg for videos. Bundle the supplied PNG logo. The user's detailed request is the product specification; implementation choices below are defaults made by the builder.

The app imports files and recursively scans folders on background workers, deduplicates canonical paths, and generates bounded thumbnails. A sequential conversion worker keeps memory and CPU predictable. The JS bridge polls a versioned queue snapshot; neither file inspection nor encoding runs on the UI thread. Imports can continue while conversion runs; the running batch has a fixed set of items and settings.

The dashboard has a floating navigation rail, header/search/utilities, upload card, filterable queue, settings card, and summary/action card. History, presets, and settings are functional views. All assets are local. System fonts and inline SVG icons avoid network dependencies. Show genuine empty states, per-file errors, real progress, and an honest estimated remaining time.

Images support JPG/JPEG, PNG, WEBP, BMP, TIFF, GIF, and AVIF as inputs and outputs when the installed Pillow build supports them. Preserve animation/multipage data when the destination supports it; explicitly report first-frame conversion otherwise. Correct EXIF orientation, composite transparency onto white for JPEG/BMP, preserve compatible metadata when requested, and never upscale. Videos support MP4, MKV, AVI, MOV, WEBM, and FLV; encode compatible video/audio codecs and report missing encoders. Preserve frame rate and audio. Same as source retains dimensions with high quality; Compress selects quality 75 and scale 75%; Match Output uses selected custom values. Formats remain independently selectable for photos and videos. With bulk mode disabled, selecting a queue item edits its own overrides.

Default output is a converted directory next to each source. A custom directory applies globally. Reserve incremented filenames exclusively, encode to temporary sibling files, and publish atomically. Originals are never replaced. Cancellation terminates FFmpeg and cleans incomplete output. Corrupt media and unsupported codecs fail per item without stopping subsequent conversions.

Detect FFmpeg on PATH or an explicit configured executable; show an actionable banner when missing. FFprobe is optional, with FFmpeg inspection as fallback. Persist preferences, named presets, and bounded conversion history atomically under the operating system's app-data directory. Closing the app cancels and cleans the active job. Provide installation/run documentation, a Windows launcher, packaging configuration, and integration tests using real media.

Alternatives: an HTTP API introduces an unnecessary service and security surface; a browser-only UI cannot handle native local paths safely. The requested pywebview bridge is the direct fit. Work in the supplied empty repository on a codex branch so the deliverable remains in the user's workspace.

The user subsequently requested audio support. Add audio to the same queue, recursive import, file picker, per-file overrides, presets, history, cancellation, and progress. Provide an independent audio destination selector and audio filter/count. Support MP3, WAV, FLAC, M4A, AAC, OGG, OPUS, AIFF, and WMA. Reuse the FFmpeg process runner; photo/video resolution settings do not affect audio. Preserve PCM precision in WAV/AIFF, support compatible surround output, and downmix multichannel input only where required by the destination. Lossy audio quality maps to encoder quality/bitrate; WAV, FLAC, and AIFF use lossless encoders. Artwork is omitted, compatible text metadata follows the global preference. Fit the native window within the current monitor's available area.
